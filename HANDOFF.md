# JunkRace — передача проекта в Claude Code

> Положи этот файл в корень Unity-проекта (можно переименовать в `CLAUDE.md`, чтобы Claude Code читал его автоматически).
> Скрипты лежат в `Assets/JunkRace/`. Подробности по запуску и управлению — `Assets/JunkRace/README.md`.

## Что за игра
Тупая весёлая кооп-игра на 1–4 игрока (в будущем больше). Игроки на свалке **руками таскают хлам**
(ванна, колёса, моторы, вентиляторы, зонт, утка) и **прикручивают его к корпусу**, собирая машину, потом едут по трассе.
Машина **разваливается от ударов**, детали можно подобрать и прикрутить обратно на ходу.

Позиционирование: не «инженерный конструктор» (Trailmakers, Besiege, Scrap Mechanic), а **Overcooked с машинами**:
сборка на время из общей кучи, хаос, короткие раунды, крики в голосовом.

## Стек (решения приняты)
- **Unity 6**, C#
- **Новая Input System** — строго, старый Input Manager не используем. Сейчас действия собраны в коде (`GameControls.cs`).
- **Netcode for GameObjects** + **Unity Multiplayer Services** (Sessions + Relay) — игра через интернет без IP/портов.
  Тот же подход уже работал в проекте CarDerby (`bzick4/CarDerby`).
- **PhysX на GameObject'ах. ECS не используем** (обсудили: активных тел мало, узкое место — сеть, а не CPU).
- UI пока на **IMGUI** (временный вид). Логика отделена от отрисовки, позже можно на UI Toolkit.

## Статус: ВАЖНО
**Весь код написан без компиляции в Unity** (в чате не было Unity). Синтаксис проверен парсером, но:
- первым делом — открыть проект, **починить ошибки компиляции**;
- самые вероятные места: имена API Multiplayer Services в `CoopSession.cs`
  (`SessionOptions`, `JoinSessionOptions.Password`, `PlayerProperty`, `VisibilityPropertyOptions`, `ISession.Players`,
  `IReadOnlyPlayer.Properties`, `session.AsHost().IsLocked`, `SavePropertiesAsync`) — сверить с версией пакета в проекте;
- затем **JunkRace → Собрать всё (меню + трасса)** и проверить соло, потом кооп через Multiplayer Play Mode.

Требования к проекту: пакеты Input System, Netcode for GameObjects, Multiplayer Services;
Active Input Handling = Input System Package (New); проект привязан к Unity Cloud (Project Settings → Services).

## Архитектура (ключевые идеи — сохранять)
1. **«Кто управляет»** — `IPartInput` (газ, руль, спец). Деталь не знает, кто жмёт: игрок, бот, сеть, автораскладка.
   `Part.InputOverride` — задел, чтобы каждая деталь слушала своего игрока (роли в коопе).
2. **«Кто авторитет»** — `Authority.IsAuthority`. Офлайн и хост = true, клиент = false.
   Физику, прикрепление, отрыв деталей и финиш решает только авторитет.
3. **Машина = один Rigidbody.** Прикрученные детали становятся детьми корпуса, их коллайдеры — составной коллайдер.
   Отдельный Rigidbody у детали только когда она свободна. Отрыв — по импульсу удара в `OnCollisionEnter`,
   выполняется отложенно в `FixedUpdate`. (Сначала думали про FixedJoint — отказались, в сети с ними мучение.)
4. **`World`** — единая точка изменений мира: `Request*` (локальный игрок хочет) → `Server*` (хост проверяет)
   → `Apply*` (применяется у всех). Офлайн/хост выполняют сразу, клиент шлёт запрос хосту.
5. **Сеть без NetworkObject'ов** (`JunkNet`): детали — объекты сцены, сетевой номер = порядок в иерархии.
   Именованные сообщения NGO: хост шлёт снапшоты позиций (20 Гц, движущиеся + понемногу спящие),
   позы игроков, надёжные события (взял/бросил/прикрутил/отвалилось/сел/вышел/финиш) и полное состояние новичку.
   Клиент шлёт свою позу, ввод и запросы. Чужие игроки — `RemoteAvatar` (капсула с именем).
   Клиент физику не считает: тела кинематические, плавно догоняют позиции хоста.
6. **Аркадная физика колёс** (`WheelPart`): луч-подвеска (пружина + демпфер), боковое сцепление `grip`,
   тяга от мотора ограничена `traction` колеса. Без WheelCollider.
   Мотор (`EnginePart`) отдельной деталью: тяга = мощность / скорость, делится на колёса на земле.
   Сопротивление воздуха ∝ v² даёт естественную максималку. Управление в воздухе при наличии руля.
7. **`VehicleStats`** — та же модель «на бумаге»: оценка максималки, разгона, веса, плавучести.
   Используется в карточке детали (было → станет) и в панели машины.

## Что уже сделано
- Меню: **Соло / Кооп / Ультра кооп (заблокирован)**.
- Кооп: имя игрока → список серверов (автообновление) → войти / по коду / создать (название + пароль, необязательный,
  от 8 символов — ограничение Unity). Лобби до **4** игроков, когда все в сборе — отсчёт 3 сек и старт;
  у хоста кнопка «Начать сейчас (тест)». После старта сессия закрывается для новых.
- Общий мир по сети: все видят друг друга, детали и машины; можно вдвоём собирать одну машину.
- Трасса: свалка → трамплин → бассейн → выезд → финиш, таймер, счётчик доехавших деталей.
- Детали на свалке: ванна (плавает), паллет (тонет), колёса тележки/квадроцикла, моторы газонокосилки/стиралки/бензопила,
  вентилятор, пылесос-турбо, руль, зонт, утка.
- Карточка детали при взгляде/в руках, панель машины (Tab), спидометр, пауза (Esc).

## Придуманные механики (план, ещё не реализованы)

### Детали (у каждой — плюс и смешной минус)
- **Корпуса:** ванна, паллет, магазинная тележка (уже с колёсами, хлипкая), шкаф (прочный, ничего не видно),
  дверь от холодильника (скользит по воде как сёрф).
- **Управление:** руль от автобуса (плавный), джойстик от приставки (резкий), весло (только в воде), поводок с собакой.
- **Двигатели:** газонокосилка, стиралка, бензопила (есть), мопедный мотор (стартовый), блендер (перегревается), хомяк в колесе.
- **Колёса:** тележки, квадроцикла (есть), офисного кресла (несёт боком), тракторное (переезжает всё), лыжи (вода/лёд).
- **Сиденья** — место для игрока (см. ниже).
- **Ускорители:** пылесос (есть), огнетушитель (короткий мощный рывок), кола с ментосом (одноразовые), фейерверк (в случайную сторону).
- **Спец:** зонт (есть), батут, магнит, **крюк-кошка**, пушка-плевалка помидорами.
- **Броня:** бампер из матраса, покрышки по бортам — детали отваливаются реже.
- Под вопросом: топливо/канистры.

### Роли в машине (главная кооп-фишка)
- Роли: **Руль**, **Педали** (газ/тормоз), **Механик**, **Бортовой** (ускоритель и спец-детали).
- Раскладка: 1 игрок — всё сам (механик упрощён до автомата); 2 — руль+педали / механик+бортовой;
  3 — руль / педали+бортовой / механик; 4 — каждому по роли.
- **Роль живёт в сиденье, а не в игроке.** На старте роли случайно раскидываются по сиденьям,
  никто не знает, что ему досталось, пока не начнёт жать кнопки.
- Игрок выпал → сиденье пустое → роль не выполняется (без педалей машина катится по инерции, без руля едет прямо).
  Можно пересесть на пустое сиденье и забрать роль.
- **Механик** — своя мини-игра. Предложено: передачи (переключать вовремя), перегрев, «завести» после того как заглох.
  **Не решено:** полный набор или проще (только «завести»). Спросить пользователя.
- Реализация: `Part.InputOverride` + привязка ролей к сиденьям.

### Сиденья, крыша, выпадение
- Нет сиденья — **едешь на крыше, как в Безумном Максе**. С крыши можно кидать крюк, стрелять, ловить детали.
- Базовые шансы выпасть: **крыша 55%**, кресло-мешок 40%, стул на колёсиках 35%, офисное кресло 30%,
  унитаз 25%, автокресло с ремнём 10% (редкое).
- Шанс = базовый × **сила толчка** (0..1), а не чистый рандом на каждой кочке.
- Кнопка **«держаться!»** на крыше: шанс вдвое меньше, но руки заняты (ни крюка, ни стрельбы).
- Выпавший бежит за машиной; **крюк-кошкой** (может пользоваться любой в машине) можно втянуть его обратно.

### Режимы
- **Соло** — есть.
- **Кооп** (до 4, одна машина) — лобби есть, роли/сиденья — в план.
- **Каждый сам за себя** — каждый строит свою машину (почти бесплатно на текущей архитектуре).
- **Боты** — готовые чертежи под трассу + езда по вейпоинтам, лёгкий «резиновый поводок».
- **Ультра кооп** — несколько команд на одной свалке, дефицит хороших деталей, саботаж
  (отклеить скотч, утащить руль, кинуть унитазом). Для начала 3×3 или 2×4. `Vehicle.TeamId` — задел.
- **Песочница / свободный режим** — 4 игрока, у каждого своя машина, без таймера, **процедурный мир по seed**
  (хост шлёт только seed, мир грузится чанками). Обязательно: **точки трюков** (трамплины, обрывы, вода)
  и **свалки по миру** для апгрейда машины на ходу.
